# Security

File gatekeepers: `packages/datasets/src/dsa_datasets/validate.py` is the only owner -- extension allowlist, the client's *declared* content type checked against a per-extension set, the file's own leading bytes rejected when they spell a container (`PK`, gzip, 7z, Rar!, and `ustar` at offset 257), 100MB limit, and `..`/separator traversal refusal in the filename. Note what is **not** in that list: `packages/execution/src/dsa_execution/mime_sniff.py` sniffs magic bytes and looks like the gatekeeper, but no shipped path calls it -- the live MIME rule is a table duplicated inside `validate.py` (the comment there says so, to avoid an import cycle). The two rules are not equivalent: over the 66 (extension, declared type, head) combinations measured on 2026-10-23 they agree on 29, and on 37 the sniffer accepts what the live gate refuses. The mechanism is its own fallback -- an unrecognized declaration is replaced by `sniff_mime`, which answers from the extension's guessed type -- so an `.xls` declared `text/csv` passes because csv is allowed for xls. Every allowed extension diverges, none runs the other way, so the sniffer is strictly looser and wiring it in would loosen the gate rather than tighten it. `tests/security/test_upload_guard.py` pins the live rule to this paragraph and pins live-accepted-imply-sniffer-accepted, so neither half can drift quietly.

SQL: `packages/execution/src/dsa_execution/sql_guard.py` — read-only allowlist `SELECT/WITH`, deny `DROP/DELETE/UPDATE/INSERT/ALTER/ATTACH/COPY/PRAGMA` and eleven file/network patterns, single-statement, row-limit enforcement. The deny list is not the whole boundary: `SELECT * FROM 'x.csv'` names none of its denied functions, reaches DuckDB's replacement scan, and did read the file. The connection therefore also sets `enable_external_access=false` before any caller statement runs -- measured, and pinned by `tests/security/test_sql_sandbox.py`.

Python: `packages/execution/src/dsa_execution/python_sandbox.py` — AST guard deny `os/subprocess/socket/requests/eval/exec/open`, safe globals, `df` injection, stdout/stderr capture + a wall-clock budget that is **enforced only where the interpreter can be interrupted**: `_LoopDeadline` puts a deadline check at every loop head, so `while True: pass` stops inside a frame of the budget (measured: 331 ms of wall clock against a 300 ms budget for the loop, 0.33 s for the C call below), while a single long call into C runs to completion and the overrun is only *reported* afterwards -- a 3200x3200 `np.matmul` against a 300 ms budget finished and then returned `TimeoutError`. The module's own docstring says this; the point of stating it here is that the budget bounds wasted *reported* time, not occupied worker time, which on a 0.5-vCPU instance is an availability lever for anyone who can reach the endpoint (open item #59). **Not a security boundary.** Measured 2026-10-23 by asking what the checker permits rather than what it names: `pl.os.walk('/')`, `pl.os.remove('…')`, `pl._dependencies.subprocess.Popen('…')` and `pl.__dict__['os']` all pass it, because polars re-exports `os` and `subprocess` so no denied name is needed, and the `ast.Subscript` branch is a comment about blocking `__builtins__.__dict__` followed by `pass`. What it does bound is a generated analysis wandering into an import by accident. It cannot bound a caller who means it, and CPython has no `enable_external_access`, so the control is which hosts can reach the endpoint -- `MCP_DESIGN.md`, `AUDIT_LEDGER.md` §265.

Prompt injection: **detector present, not wired.** `packages/execution/src/dsa_execution/guardrails.py` (`contains_prompt_injection`, `sanitize_untrusted_text`) and `dsa_agent.critic.detect_prompt_injection` are implemented and unit-tested, but no shipped code path calls them, so dataset cell text is currently neither scanned nor tagged. Do not treat this as a control until a caller exists.

Claim discipline: enforced. `check_unsupported_claims` (`packages/agent/src/dsa_agent/critic.py:90`) emits the `unsupported_claim` validation, which is in `HARD_FAIL_CHECKS` (`packages/agent/src/dsa_agent/graph.py:51`, applied at `:631`), so an unsupported causal claim fails the run. The textual helper `rewrite_unsupported_claim` (in `guardrails.py` and `critic.py`) is not applied to any output — claims are failed, not reworded.

Resource budgets: `check_resource_limits` (tool calls / tokens / execution time) → `WAITING_FOR_APPROVAL / HUMAN_REVIEW`.

Tests: `tests/security/test_security_phase8.py` (prompt injection / path traversal / code injection / malicious file / SQL injection / output guard / budget / HITL), `tests/security/test_upload_guard.py` (the file gatekeepers reading the bytes, and the documented extension set), `tests/security/test_sql_sandbox.py` (the SQL fence, both directions), `tests/security/test_artifact_containment.py` (artifact writes, the reader's climb, the bundle classifier).
