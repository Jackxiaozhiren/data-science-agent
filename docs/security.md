# Security

File gatekeepers: `packages/datasets/src/dsa_datasets/validate.py` + `packages/execution/src/dsa_execution/mime_sniff.py` — allowlist ext/MIME, `head` magic peek, `..` traversal block, 100MB limit, archive block.

SQL: `packages/execution/src/dsa_execution/sql_guard.py` — read-only allowlist `SELECT/WITH`, deny `DROP/DELETE/UPDATE/INSERT/ALTER/ATTACH/COPY/PRAGMA` and eleven file/network patterns, single-statement, row-limit enforcement. The deny list is not the whole boundary: `SELECT * FROM 'x.csv'` names none of its denied functions, reaches DuckDB's replacement scan, and did read the file. The connection therefore also sets `enable_external_access=false` before any caller statement runs -- measured, and pinned by `tests/security/test_sql_sandbox.py`.

Python: `packages/execution/src/dsa_execution/python_sandbox.py` — AST guard deny `os/subprocess/socket/requests/eval/exec/open`, safe globals, `df` injection, stdout/stderr capture + wall-clock timeout. **Not a security boundary.** Measured 2026-10-23 by asking what the checker permits rather than what it names: `pl.os.walk('/')`, `pl.os.remove('…')`, `pl._dependencies.subprocess.Popen('…')` and `pl.__dict__['os']` all pass it, because polars re-exports `os` and `subprocess` so no denied name is needed, and the `ast.Subscript` branch is a comment about blocking `__builtins__.__dict__` followed by `pass`. What it does bound is a generated analysis wandering into an import by accident. It cannot bound a caller who means it, and CPython has no `enable_external_access`, so the control is which hosts can reach the endpoint -- `MCP_DESIGN.md`, `AUDIT_LEDGER.md` §265.

Prompt injection: **detector present, not wired.** `packages/execution/src/dsa_execution/guardrails.py` (`contains_prompt_injection`, `sanitize_untrusted_text`) and `dsa_agent.critic.detect_prompt_injection` are implemented and unit-tested, but no shipped code path calls them, so dataset cell text is currently neither scanned nor tagged. Do not treat this as a control until a caller exists.

Claim discipline: enforced. `check_unsupported_claims` (`packages/agent/src/dsa_agent/critic.py:90`) emits the `unsupported_claim` validation, which is in `HARD_FAIL_CHECKS` (`packages/agent/src/dsa_agent/graph.py:51`, applied at `:631`), so an unsupported causal claim fails the run. The textual helper `rewrite_unsupported_claim` (in `guardrails.py` and `critic.py`) is not applied to any output — claims are failed, not reworded.

Resource budgets: `check_resource_limits` (tool calls / tokens / execution time) → `WAITING_FOR_APPROVAL / HUMAN_REVIEW`.

Tests: `tests/security/test_security_phase8.py` (prompt injection / path traversal / code injection / malicious file / SQL injection / output guard / budget / HITL), `tests/security/test_upload_guard.py` (the file gatekeepers reading the bytes, and the documented extension set), `tests/security/test_sql_sandbox.py` (the SQL fence, both directions), `tests/security/test_artifact_containment.py` (artifact writes, the reader's climb, the bundle classifier).
