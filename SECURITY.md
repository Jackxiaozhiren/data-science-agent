# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| 2.0.x   | Yes       |
| 4.1.x   | Yes       |
| < 2.0   | Best-effort only |

## Reporting a Vulnerability

Report privately via GitHub Security Advisories (preferred) or open a private GitHub Issue titled `[SECURITY]`. Do not disclose publicly before a fix is coordinated. Expect an initial response within 3 business days.

## Sandbox Model

- **File**: MIME sniff + extension allowlist, 100 MB cap, archive-bomb guard, path traversal block (`packages/execution/file_validator.py`).
- **SQL**: Read-only allowlist (`SELECT/WITH/SHOW/DESCRIBE/EXPLAIN`), row limit `10k`, no `INSERT/UPDATE/DELETE` (`sql_validator.py` + `run_sql`).
- **Python**: AST allowlist, `_safe_import` deny `os/subprocess/socket/requests/eval/exec/open/__import__`, allowed `{polars, numpy, math, statistics, json, re, datetime, collections, itertools}`, 5s wall-clock (`python_sandbox.py`).
- **Prompt injection**: Dataset is `UNTRUSTED DATA`, pattern detection `PROMPT_INJECTION_PATTERNS`, output causal-claim rewrite (`guardrails.py` + `dsa_agent/critic.py`).
- **Resource limits**: Tool budgets `max_steps 20 / max_tool_calls 40 / max_retries 3` (`packages/agent/graph.py`) + evidence coverage gating.

## Supply Chain & Security Hardening

- **Dependabot**: `.github/dependabot.yml` weekly for `pip` (`/`), `npm` (`apps/web`), `docker` (`/`).
- **Code Scanning / CodeQL**: `.github/workflows/codeql.yml` analyzes `python` + `javascript` on push/PR weekly.
- **Dependency Review**: `.github/workflows/dependency-review.yml` checks PR for `vulnerability/license/dependency change`.
- **Secret Scanning / Push Protection**: GitHub Secret Scanning + `gitleaks` via `.github/workflows/secret-scan.yml` scans full history for hard-coded credentials. No `API keys/tokens/passwords` in repo, history, CI artifacts, logs.
- **Plugin Supply Chain**: `PluginManifest.validate_manifest()` checks `malicious plugin`, `dependency confusion`, `typosquatting` (Levenshtein ≤2 vs popular), `malicious dependency`, `arbitrary code` — see `packages/plugins/src/dsa_plugins/manifest.py`.
- **Dependency Pinning**: `uv.lock` is committed, `uv lock --check` in CI, `pyproject.toml` versioned deps, dev vs runtime separated (`dependency-groups.dev` vs `dependencies`).
- **SBOM**: `release/sbom.json` + `release/sbom.cyclonedx.json` generated by `scripts/generate_sbom.py` (package, version, license, source) — 192 components.

## Publishing

Releases are built and verified in CI, then tagged and released on GitHub. PyPI publishing
should use **Trusted Publishing (OIDC)** so no long-lived token is stored: a dedicated
`release` workflow, pinned by commit SHA, uploading the built wheel + sdist, with artifact
attestations generated by the GitHub release. No PyPI credentials exist in this repository's
history or CI — nothing to rotate.

> **Status:** PyPI publish is not yet enabled (no OIDC trust configured on the project).
> Until it is, install from source (`pip install .` / `uv sync`) or use the GitHub release
> artifacts. See `CHANGELOG.md` for the latest published version.

## Known Limitations

- Physical host compromise, upstream dependency supply-chain outside `uv.lock`, social engineering of reviewers, denial-of-wallet on paid LLM providers (local-first `stub` avoids this).

Security boundary details: see [`docs/security.md`](docs/security.md).
